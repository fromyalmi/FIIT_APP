## 0) 이 문서의 목적 (1분 요약)
우리 팀은 7인이 **동시에 개발**합니다. 그래서 “각자 마음대로” 하면 통합할 때 터집니다.  
이 문서는 **병렬 개발이 가능하도록 만드는 최소 계약서**입니다.

---

## 1) 절대 고정(병합 조건) — 이거 4개 깨지면 통합 불가
1) **입력 UI는 왼쪽 사이드바에만** 둔다.  
- 본문(view)은 결과 출력만 한다. (본문에 입력칸 만들지 말기)

2) **Streamlit 위젯은 항상 `key=` 고정**한다.  
- 같은 라벨/구성 위젯이 여러 번 생성되면 `DuplicateElementId`가 터진다.

3) **view 엔트리 함수명은 `render()`로 통일**한다.  
- main.py에서 `from views.xxx import render as render_xxx`로 고정 호출한다.

4) **CH별 generator “외부 공개 함수” + 반환 dict 키는 고정**한다.  
- 내부 구현/보조 함수명/프롬프트는 마음대로 개선 가능.  
- 하지만 아래 “계약”을 깨면 main/view가 결과를 못 읽는다.

---

## 2) 수정 권한(소유권) — 팀장 승인 없이 수정 금지
### 🔒 팀장 승인 없이 수정 금지 (공통 계약 파일)
- `app/main.py`
- `app/core/common/schema.py`
- `app/core/common/result.py`
- `app/core/common/ui.py`
- `app/core/common/storage.py`
- (필요 시) `app/core/common/validators.py`, `app/core/common/llm.py`

> 팀원이 공통을 바꾸고 싶으면: “왜/무엇을/어디를” 바꾸는지 팀장에게 먼저 공유 후 반영.

---

## 3) 팀원이 자유롭게 수정 가능한 범위
- CH1(광고 2인): `app/core/ch1/*`, `app/views/ch1_ads.py`
- CH2(영상 2인): `app/core/ch2/*`, `app/views/ch2_video.py`
- CH3(SNS 2인): `app/core/ch3/*`, `app/views/ch3_sns.py`
- 테스트/문서: `scripts/*`, `docs/*`

---

## 4) 함수 계약(시그니처/키) — 절대 고정
### CH1 광고
- 호출: `generate_ads(input_obj, mock=False)`
- 반환(dict) 키: `items`, `saved_path`
- session_state 키: `st.session_state["ch1_result"]`

예시:
```json
{ "items": ["문구1", "문구2"], "saved_path": "outputs/ads_result_YYYYMMDD_HHMM.json" }
```

### CH2 영상
- 호출: `generate_video_script(input_obj, mock=False)`
- 반환(dict) 키: `title`, `script`, `hashtags`, `saved_path`
- session_state 키: `st.session_state["ch2_result"]`

예시:
```json
{ "title": "제목", "script": "본문", "hashtags": ["#태그"], "saved_path": "outputs/video_result_YYYYMMDD_HHMM.json" }
```

### CH3 SNS/블로그
- 호출: `generate_sns_post(input_obj, mock=False)`
- 반환(dict) 키: `caption`, `hashtags`, `saved_path`
- session_state 키: `st.session_state["ch3_result"]`

예시:
```json
{ "caption": "본문", "hashtags": ["#태그"], "saved_path": "outputs/sns_result_YYYYMMDD_HHMM.json" }
```

---

## 5) UI 규칙 (A안: “현재 메뉴만” 사이드바 입력 노출)
- 상단 메뉴는 **서버가 선택값을 아는 방식**으로 관리한다. (예: `st.radio(..., horizontal=True, key="nav_main")`)  
- 현재 선택 메뉴에 해당하는 입력 폼만 사이드바에 표시한다.  
- 본문(view)은 입력 UI를 만들지 말고 결과만 보여준다.  
- 위젯 key 규칙: `prefix__field` (예: `ch1__menu_name`)
